# NS32000 (`ns32k`) UPCL Frontend — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Describe the complete National Semiconductor NS32000 (Series 32000) ISA as a single runtime-interpreted UPCL file `upcl/examples/ns32k.upcl`, backed by three small generic decoder extensions, executable across four `cpu` variants.

**Architecture:** Three additive, generic extensions to the UPCL engine (`LibCPU/upcl/`) supply the encoding machinery NS32000 needs — per-field big-endian override, self-describing variable-length displacement (multiple per addrmode rule), and nested scaled-index dispatch. The ISA itself is then pure UPCL data: one `arch "ns32k"` block, one parameterized `gen` addrmode, integer instructions at top level, and `feature fpu/mmu/cache` blocks selected by four `cpu` declarations.

**Tech Stack:** C++20 (engine: `Ast.h`, `Parser.cpp`, `Decoder.cpp`), the UPCL DSL (the `.upcl` data), CMake/CTest (`LibCPU/CMakeLists.txt`), `lcx` CLI for check/decode/disasm/run.

## Global Constraints

- Coding style: NT style, `_underscore_tags`, UPPERCASE typedefs, PascalCase enum values; UEFI comment style; 4-space indent; `if (x) { oneline }`; no useless `{ }`; one-level `P<type>`/`PC<type>` typedefs only.
- `LL`/`ULL` literals use `INT64_C`/`UINT64_C`; `~UINT64_C(0)` for all-ones.
- Fix the cause, never silence a warning; never simplify tests.
- Target MSVC and OpenWatcom where possible (engine C++ is C++20 — note OpenWatcom cannot build C++20; keep new code within what the existing `upcl` library already requires).
- Run `clang-format` on touched C++ before committing **only** if the file is already clang-format-clean; this repo has NO `.clang-format` and hand-maintained NT style must be preserved — match style by hand, do not bulk-reformat.
- Engine extensions are strictly additive: existing `.upcl` ISAs (pdp11, mips, m88k, x86, 6502, …) must decode byte-identically after each change. Re-run their existing ctests as regression after every engine task.
- Arch identifier / filename / test names: `ns32k`. Human-readable arch name: "National Semiconductor NS32000". CPU model strings: `ns32032`, `ns32332`, `ns32532`, `ns32732`.
- Commit only the files each task lists. Do not `git push` or open PRs unless the user asks.
- **Opcode sourcing (binding):** all NS32000 instruction encodings (Format 0–11 opcode bytes, gen-field placement, operand-length field positions, branch/disp layout) MUST be sourced from the authoritative GNU binutils `ns32k` tables — `include/opcode/ns32k.h`, `opcodes/ns32k-dis.c`, `gas/config/tc-ns32k.c` — or the NS32000 Programmer's Reference Manual. Do NOT invent opcode values. Every decode test MUST assert a **real** byte sequence (one a real NS32000 assembler would emit), so the test validates correctness against the architecture, not merely internal self-consistency.
- **Build location:** the engine C++ changes must be compiled in *this worktree*. Configure once with `cmake -S LibCPU -B LibCPU/build` (or the project's documented configure step) and build the `lcx` target; run tests with `ctest --test-dir LibCPU/build`. The prebuilt `lcx` in the original checkout does NOT reflect worktree source and must not be used.

## Reference facts (used throughout)

- **PSR bit layout (LSB→MSB):** `C(0) T(1) L(2) ·(3) ·(4) F(5) Z(6) N(7) U(8) S(9) P(10) I(11)`; bits 12-15 reserved.
- **`gen` 5-bit modes:** see the table in the spec §6. Low 3 bits = register number for modes `00000–01111`.
- **Variable-length displacement (big-endian):** first byte top bit `0` → 1 byte / 7-bit signed (range −64..63); top bits `10` → 2 bytes / 14-bit signed; top bits `11` → 4 bytes / 30-bit signed.
- **Operand length field `i`:** `00`=byte (1), `01`=word (2), `11`=double (4).
- **`CMP` flags:** `Z=(a==b)`, `N=(a>b)` signed, `L=(a>b)` unsigned.
- Existing template to imitate: `upcl/examples/pdp11.upcl`.

### Task 2: E2 — self-describing variable-length displacement (`disp varlen`), multiple per rule

**Files:**
- Modify: `LibCPU/upcl/Ast.h` (displacement carrier in `AddrTerm`: add `DispEncoding` enum + allow an ordered list of disp terms per rule)
- Modify: `LibCPU/upcl/Parser.cpp` (addrmode address-term parser ~line 1307-1326: accept `disp varlen`, allow >1 disp per rule)
- Modify: `LibCPU/upcl/Decoder.cpp` (`ResolveAddrMode` disp-extraction block ~line 241-319)
- Test: `upcl/examples/_test_varlen.upcl` + ctest

**Interfaces:**
- Consumes: nothing from Task 1 (independent), but coexists with `BigEndian`.
- Produces: `enum class DispEncoding { Fixed, VarLen };` on the disp carrier; addrmode rules may carry an ordered `std::vector` of disp terms, each resolved left-to-right against the advancing tail cursor. Grammar: `disp varlen` (and `disp varlen be` combines with E1). The NS32000 varlen scheme: read first tail byte; `(b & 0x80)==0` → 1 byte, value = sign-extend 7-bit (`b & 0x7F`); `(b & 0xC0)==0x80` → 2 bytes, 14-bit signed; `(b & 0xC0)==0xC0` → 4 bytes, 30-bit signed; bytes are big-endian; cursor advances by 1/2/4.

- [ ] **Step 5: Decode varlen in `ResolveAddrMode`**

In `LibCPU/upcl/Decoder.cpp`, replace the fixed-width disp logic (currently ~line 274-280) with a branch on `DispKind`. For `VarLen`, implement:
```cpp
//
// NS32000-style self-describing displacement: the top bits of the first
// byte select the encoded width. Bytes are big-endian; the value is
// sign-extended from the encoded bit width.
//
UINT8 CONST B0 = pTail[0];
UINT32 DispBytes;
UINT32 DispBits;
if ((B0 & 0x80) == 0) { DispBytes = 1; DispBits = 7; }
else if ((B0 & 0xC0) == 0x80) { DispBytes = 2; DispBits = 14; }
else { DispBytes = 4; DispBits = 30; }
if (DispBytes > TailAvail) { return FALSE; }
UINT64 Raw = 0;
for (UINT32 i = 0; i < DispBytes; ++i) { Raw = (Raw << 8) | pTail[i]; }  // big-endian
Raw &= (DispBytes == 4) ? UINT64_C (0x3FFFFFFF)
     : (DispBytes == 2) ? UINT64_C (0x3FFF) : UINT64_C (0x7F);
pOut->Disp = SignExtend (Raw, DispBits);
*pExtraBytes += DispBytes;
```
Iterate this over each disp term in the rule's ordered list, advancing `pTail`/`TailAvail`/`*pExtraBytes` between terms.

- [ ] **Step 5: Decode the index byte and recurse**

In `LibCPU/upcl/Decoder.cpp` `ResolveAddrMode`, when a term carries a non-empty `NestedAddrMode`:
```cpp
if (TailAvail < 1) { return FALSE; }
UINT8 CONST IndexByte = pTail[0];
UINT64 CONST BaseGen = (IndexByte >> T.NestedRegBits) & ((1u << T.NestedSelBits) - 1);
UINT64 CONST IReg    = IndexByte & ((1u << T.NestedRegBits) - 1);
std::map<std::string, UINT64> NestedFields;
NestedFields[/*nested param name, e.g. "g"*/] = BaseGen;
Operand NestedOp;
UINT32 NestedExtra = 0;
if (!ResolveAddrMode (/*the @NestedAddrMode field*/, NestedFields,
                      pTail + 1, TailAvail - 1, &NestedExtra, &NestedOp)) { return FALSE; }
*pExtraBytes += 1 + NestedExtra;             // index byte + nested mode's extension bytes
// Combine: pOut base = NestedOp base/disp; add scaled index register IReg * T.Scale.
```
Look up the `@NestedAddrMode` rule by name from the arch's addrmode table; map `BaseGen` to its single parameter; merge the resolved base EA with the scaled index register into `pOut`.
