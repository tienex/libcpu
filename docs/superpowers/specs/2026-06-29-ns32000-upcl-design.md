# NS32000 UPCL Frontend — Design

Date: 2026-06-29
Branch: feat/com-core (work in worktree `ns32000-upcl`)
Status: approved scope, pending spec review

## 1. Goal

Describe the National Semiconductor NS32000 (Series 32000) instruction set as a
single UPCL description, runtime-interpreted by the LibCPU framework, with no
per-ISA C++ glue beyond a small set of *generic, reusable* decoder extensions.
The architecture identifier, filename, and test names use `ns32k` (the common
Unix/GCC toolchain name for the family); the human-readable arch name remains
"National Semiconductor NS32000". The result is driven by:

```
lcx upcl check  upcl/examples/ns32k.upcl
lcx upcl decode upcl/examples/ns32k.upcl <hex bytes>
lcx disasm <file> --arch upcl:upcl/examples/ns32k.upcl
lcx run    <file> --arch upcl:upcl/examples/ns32k.upcl@ns32532
```

Coverage is the **complete** user + system ISA: integer core, NS32081/381 FPU,
and NS32082/382 / on-chip MMU + privileged operations.

## 2. Why the NS32000 is interesting (and hard)

The NS32000 is one of the most orthogonal CISC architectures ever shipped: any
addressing mode pairs with any operand of any instruction, eight fully general
32-bit registers, no special-casing. The cost of that regularity is a richly
self-describing, variable-length encoding:

- An instruction is 1–3 opcode bytes carrying up to two 5-bit **gen** (general
  addressing mode) fields, followed by per-operand extension bytes (index
  bytes, displacements, immediates) appended *in order* — gen1's extensions
  first, then gen2's. Total length is computed only by decoding both operands.
- **Displacements are self-describing and big-endian**: the top bits of the
  first displacement byte choose the width — `0` → 1 byte (7-bit signed),
  `10` → 2 bytes (14-bit signed), `11` → 4 bytes (30-bit signed) — inside an
  otherwise little-endian ISA.
- **Immediates are big-endian**, width = the instruction's operand length.
- **Scaled-index** gen values consume an extra index byte that itself names
  another (nested) gen mode.

## 3. Layout decision

Single file `upcl/examples/ns32k.upcl` (`arch "ns32k"`), matching the PDP-11 template: shared
base ISA at top level, optional units wrapped in inline `feature fpu { … }`,
`feature mmu { … }`, `feature cache { … }` blocks, and four `cpu "…"`
declarations selecting features. (Modular split was considered and rejected:
four closely-related variants whose only separable units are FPU/MMU/cache do
not justify include files.)

## 4. Engine extensions (generic, additive)

All three are additive to the existing `upcl` library — existing ISAs are
byte-for-byte unaffected. Each ships with its own focused decode test so it is
verified independently of NS32000. They are intentionally generic (a future
VAX frontend needs E1 and E2 verbatim).

### E1 — per-field big-endian override (`be`)

A boolean on `EncField` (encode fields) and on displacement terms, surfaced as
a `be` keyword in the grammar, that overrides the architecture-wide endianness
for that one field. NS32000 is `endian little`, but its displacements and
immediates are big-endian.

- `Ast.h`: add `bool BigEndian = false;` to `EncField` and to the displacement
  carrier in `AddrTerm`.
- `Parser.cpp`: accept `be` after a field/disp spec.
- `Decoder.cpp`: pass `F.BigEndian ? false : m_pArch->Little` into
  `ExtractField`.

### E2 — self-describing variable-length displacement (`disp varlen`)

A new displacement encoding mode. At decode time the decoder reads the first
displacement byte from the tail, inspects its top bits to select 1/2/4 bytes,
extracts big-endian, sign-extends from the encoded width (7/14/30 bits), and
advances the tail cursor by the consumed byte count.

Generalized beyond the current one-displacement-per-rule model: **multiple
`disp` terms may appear in a single addrmode rule**, each consuming the next
bytes of the tail left-to-right. Required by the memory-relative modes, which
carry two displacements.

- `Ast.h`: add a `DispEncoding` enum (`Fixed`, `VarLen`) to the displacement
  carrier; allow a rule to hold an ordered list of displacement terms.
- `Parser.cpp`: accept `disp varlen` (and keep `disp`/`disp8`/`disp16` for the
  fixed case); allow more than one per rule.
- `Decoder.cpp`: in the disp-extraction block of `ResolveAddrMode`, branch on
  `DispEncoding`; for `VarLen`, do the read-first-byte/select-width/sign-extend
  sequence and bump `*pExtraBytes` accordingly; iterate over the rule's
  displacement list in order.

### E3 — nested index-byte dispatch (scaled index)

An addrmode rule can consume one index byte laid out `(basegen:5)(ireg:3)`,
recurse into the gen addrmode using `basegen` (which may itself read its own
displacement), and form `EA = base_EA + R[ireg] * scale`.

- `Ast.h`: add nested-dispatch metadata to `AddrTerm` (the addrmode to recurse
  into, the selector/reg sub-field widths, the scale).
- `Parser.cpp`: syntax to express "read an index byte and dispatch into a named
  addrmode" inside an addrmode address expression.
- `Decoder.cpp`: in `ResolveAddrMode`, when a term carries nested-dispatch
  metadata, read the index byte, extract sub-fields, recurse, combine the base
  EA with the scaled index, and account for `1 + nestedExtra` bytes.

## 5. Register model

```
register_file {
    group R { [ 8 ** #i32 r?:0 ] }              // R0..R7

    group S {
        [ #i32 pc -> %PC ],
        [ #i32 sp0 ], [ #i32 sp1 ],             // interrupt / user stacks
        [ #i32 sp ],                            // active SP (selected by PSR.S)
        [ #i32 fp ], [ #i32 sb ], [ #i32 intbase ],
        [ #i16 mod ], [ #i32 cfg ],
        [ #i16 psr -> %PSR #i16 explicit
            ( #i4 0 : #i1 I : #i1 P : #i1 S : #i1 U
            : #i1 N -> %N : #i1 Z -> %Z : #i1 F : #i2 0 : #i1 L : #i1 T : #i1 C -> %C ) ]
    }

    feature fpu {
        group F  { [ 8 ** #f32 f?:0 ] }         // F0..F7 (single)
        group L  { [ 4 ** #f64 l?:0 ] }         // L0/L2/L4/L6 (double, overlay F pairs)
        group FS { [ #i32 fsr ] }
    }

    feature mmu {
        group M { /* PTB0 PTB1 MSR/MCR BPR PF SC TEAR IVAR … */ }
    }
}
```

PSR bit layout (LSB first): `C(0) T(1) L(2) ·(3) ·(4) F(5) Z(6) N(7) U(8)
S(9) P(10) I(11)`. `C`, `Z`, `N` bind the meta-roles `%C`/`%Z`/`%N`; `L`, `F`,
`T`, `I`, `P`, `U`, `S` are named flags.

`SP` aliases `SP0` or `SP1` per `PSR.S`; the privileged register transfers
(`LPRi`/`SPRi`) reach `SP0`/`SP1`/`US`/`FP`/`SB`/`PSR`/`INTBASE`/`MOD`/`CFG`.

## 6. Addressing-mode (`gen`) model

One `gen` addrmode parameterized by the 5-bit field value `g`, applied to both
operand slots. The decoder already accumulates trailing bytes across two
`@gen` operands in order; E2/E3 supply the missing displacement and index
machinery.

| `g` (5-bit) | Mode | Notes |
|-------------|------|-------|
| `00000–00111` | `Rn` register direct | reg = `g & 7` |
| `01000–01111` | `disp(Rn)` register relative | one varlen disp |
| `10000` | `disp2(disp1(FP))` memory relative | two varlen disps + mid deref |
| `10001` | `disp2(disp1(SP))` | two varlen disps |
| `10010` | `disp2(disp1(SB))` | two varlen disps |
| `10011` | reserved | decode error |
| `10100` | immediate | src-only, big-endian, width = operand length |
| `10101` | `@disp` absolute | one varlen disp |
| `10110` | `EXT(disp1)+disp2` external | MOD-table indirection, two varlen disps |
| `10111` | `TOS` top of stack | read pops / write pushes current SP |
| `11000` | `disp(FP)` | one varlen disp |
| `11001` | `disp(SP)` | one varlen disp |
| `11010` | `disp(SB)` | one varlen disp |
| `11011` | `disp(PC)` PC-relative | one varlen disp |
| `11100` | `[Rn:B]` scaled index, scale 1 | index byte + nested gen (E3) |
| `11101` | `[Rn:W]` scaled index, scale 2 | |
| `11110` | `[Rn:D]` scaled index, scale 4 | |
| `11111` | `[Rn:Q]` scaled index, scale 8 | |

### The three hard modes

- **TOS** (`10111`): the operand *is* the top of stack on the current SP. A
  source read pops (SP += operand length, after read); a destination write
  pushes (SP -= operand length, before write). Direction is operand-context
  dependent, modeled with `pre`/`post` side-effect blocks distinguished by the
  read vs. write rule selected for the slot.
- **Memory-relative** (`10000–10010`): `EA = disp2 + mem[base + disp1]` — two
  varlen displacements with a memory dereference between them. Requires E2's
  multi-disp-per-rule generalization.
- **External** (`10110`): `EXT(disp1)` resolves a variable through the module
  linkage table referenced by `MOD`; `disp2` adds an offset. Modeled as nested
  dereferences through `MOD`.

## 7. Operand-width (B/W/D) suffix

The 2-bit `i` length field (`00`=byte, `01`=word, `11`=double) sets the operand
width for the whole instruction. Handled with the proven PDP-11 per-rule
width-pinning pattern: width-specific gen rules (`#i8`/`#i16`/`#i32`) selected
by separate `i=00/01/11` encodings. A width-from-field engine helper will be
considered during implementation only if the encoding explosion proves
unreasonable; the explicit approach is the default (no premature engine work).

## 8. Instruction coverage

Top-level (all variants):

- **Data movement**: `MOVi`, `MOVQi` (quick), `MOVZBW/MOVZiD/MOVXBW/MOVXiD`
  (zero/sign extend), `ADDR` (load effective address), `MOVMi`.
- **Integer ALU**: `ADDi/ADDCi/ADDQi/SUBi/SUBCi/NEGi/ABSi/CMPi/CMPQi/CMPMi`,
  `MULi/QUOi/REMi/DIVi/MODi/DEIi/MEIi` (extended multiply/divide).
- **Logical / shift**: `ANDi/ORi/BICi/XORi/COMi/NOTi`,
  `LSHi/ASHi/ROTi` (shift/arith-shift/rotate, signed count).
- **Bit / bit-field**: `TBITi/SBITi/CBITi/IBITi` (+ interlocked `SBITIi/CBITIi`),
  `FFSi` (find first set), `EXTi/INSi` (bit-field extract/insert),
  `EXTSi/INSSi` (short forms), `CVTP` (convert to bit pointer).
- **Array / bounds**: `CHECKi`, `INDEXi`.
- **String**: `MOVSi/CMPSi/SKPSi` with option byte (B backward, W while-match,
  U until-match, T translate via R3) and the `MOVST/CMPST/SKPST` translated
  forms; loop on R0 count, pointers R1/R2.
- **BCD**: `ADDPi/SUBPi`.
- **Stack / frame**: `SAVE/RESTORE` (register-list bitmask), `ENTER/EXIT`
  (frame build/teardown with register list + local size), `JSR/BSR/RET`,
  `CXP/CXPD/RXP` (module call/return), `RETT/RETI` (return from trap/interrupt).
- **Control transfer**: `JUMP` (`type branch`), `BR` (unconditional, varlen
  disp), `Bcond` (the 14 conditions), `CASEi` (jump table), `ACBi`
  (add-compare-branch loop).
- **Processor control**: `LPRi/SPRi` (load/store processor register),
  `ADJSPi`, `BISPSRi/BICPSRi`, `SETCFG`, `FLAG/SVC/BPT/WAIT/DIA/NOP`,
  traps → `@trap(vector)`.

`feature fpu` (NS32081/381):

- `MOVf/MOVLF/MOVFL`, `MOVif/ROUNDfi/TRUNCfi/FLOORfi` (convert),
  `ADDf/SUBf/MULf/DIVf/NEGf/ABSf/CMPf`, `LFSR/SFSR` (status reg),
  `POLYf/DOTf/SCALBf/LOGBf` (381 extensions, feature-gated within `fpu`).

`feature mmu` (NS32082/382 / on-chip):

- `LMR/SMR` (load/store MMU register), `RDVAL/WRVAL` (validate access),
  `MOVSUi/MOVUSi` (move across user/supervisor space).

`feature cache` (532+):

- `CINV` (cache invalidate).

### Bcond condition table

`EQ Z` · `NE !Z` · `CS C` · `CC !C` · `HI L` · `LS !L` · `GT N` · `LE !N` ·
`FS F` · `FC !F` · `LO (!L&!Z)` · `HS (L|Z)` · `LT (!N&!Z)` · `GE (N|Z)`.

(`N` = signed-greater result, `L` = unsigned-greater result — see §9.)

## 9. Semantics notes (NS32000 quirks)

- **Comparison flags are non-conventional.** `CMPi src1, src2` sets
  `Z = (src1 == src2)`, `N = (src1 > src2)` *signed*, `L = (src1 > src2)*
  *unsigned*. `N`/`L` are greater-than results, **not** sign/borrow. These are
  set explicitly in the instruction body, not via a generic `%CC`. Arithmetic
  ops set `C` (carry/borrow) and `F` (signed overflow) per the manual.
- **Bit instructions** compute a byte address + bit-within-byte from the base
  and a (possibly negative) bit offset; the interlocked variants are atomic.
- **Bit-field** `EXT/INS` take an offset operand and an immediate length.
- **String** instructions loop with R0 = element count, R1 = src ptr, R2 = dst
  ptr, R3 = translation table base; honor the option byte; update PSR.F on
  match/until termination.
- **Module calls** `CXP`/`RXP` push/pop `MOD` + `PC`, reload `SB` from the new
  module descriptor.
- Traps/supervisor calls (`SVC/BPT/FLAG/trap`) vector via `INTBASE` →
  `@trap(vector)`.

## 10. CPU variants

```
cpu "ns32032" { fpu; mmu; }            // 082 external MMU, 081 FPU
cpu "ns32332" { fpu; mmu; }            // 382 MMU, 32-bit bus
cpu "ns32532" { fpu; mmu; cache; }     // on-chip MMU + cache, CINV
cpu "ns32732" { fpu; mmu; cache; }     // most-advanced member (assumption — see note)
```

> **Assumption (open):** `ns32732` is treated as the most-advanced family
> member (Swordfish-class) with the full feature set. If a specific die is
> meant, only this block changes.

## 11. Testing

Following the existing `upcl.decode-*` / `upcl.<isa>-*` conventions in
`LibCPU/CMakeLists.txt`:

- `upcl.check-ns32k` — `lcx upcl check` parses the file clean.
- `upcl.ns32k-disp-varlen` — decode the same displacement at 1/2/4-byte
  boundaries (E2), asserting width and sign.
- `upcl.ns32k-bigendian` — decode a big-endian immediate (E1).
- `upcl.ns32k-index` — decode a scaled-index operand (E3).
- `upcl.ns32k-gen-modes` — one decode per gen mode, including the three hard
  modes (TOS, memory-relative, external).
- `upcl.decode-ns32k` — disasm spot-checks for representative ALU, branch,
  string, FPU, MMU instructions.
- `upcl.ns32k-run` — `lcx run` a small NS32000 a.out exercising ALU + branch
  + a string op, asserting stdout.
- Engine extensions E1–E3 additionally get focused decode tests using a tiny
  synthetic `.upcl` so they are verified independently of NS32000.

## 12. Phasing (for the implementation plan)

1. **Engine E1–E3**, each TDD with its own decode test. Must land first.
2. **Core `ns32k.upcl`**: arch header + register file + `gen` addrmodes +
   integer ISA + the four `cpu` blocks; `lcx upcl check` green.
3. **`feature fpu`**, then **`feature mmu`**, then **`feature cache`**.
4. **Verification**: per-mode decode tests, per-variant checks, the `lcx run`
   smoke test; run the full ctest suite and `clang-format` the touched C++.

## 13. Out of scope (this pass)

- Cycle-accurate timing of the NS32000 pipeline.
- The graphics/DSP extensions of the embedded NS32CG16/NS32GX320 (BITBLT etc.).
- Hardware-level MMU page-table walking beyond what the privileged instructions
  require for decode/disasm/execute correctness.
